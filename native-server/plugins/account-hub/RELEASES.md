# 0.3.9：事件提示、原路阻击与匹配体验

- 修复远程对局事件不弹窗、不显示免打扰标签；权威事件去重交付，历史记录保留。
- 阻击时沿原路线接近，只对最后一段接敌路径寻路；攻占后回到原路线，避免辅助目标引发全程重新寻路的连锁反应。
- 极速人机仍强制标准难度，规划周期从 24～36 游戏小时缩短至 4 小时，及时集结、增援与进攻。
- 胜利结算显示权威经验增长、分段等级进度和跨等级动画，支持零经验与减少动态效果。
- 联机等待增加取消匹配；超过 45 秒建议人机，确认取消后切换；刷新页面恢复匹配状态，已配对的战局不会误报取消成功。

实现与验证说明见 `docs/events-interception-matchmaking.md`。

# 0.3.8：性能诊断、可靠同步与 Node 加速

- 对局左下角增加“性能”面板：服务 CPU 与内存（包含模拟子进程）、整机负载、模拟/同步耗时、状态包积压、本机 FPS、调兵处理及状态确认延迟；可以复制不含账号令牌的诊断数据。
- 修复发送队列覆盖增量包导致兵线更新漏收的问题，合并保留未发送的单位、据点、删除与战役信息；全量同步与读档使用版本/代次边界。
- 增加命令接收及处理回执，生效确认仍核对权威状态。顶部提示跟随确认阶段更新，避免确认后仍停留“已发送”；拦截路径按最终逻辑目标确认。
- 服务端推进不再生成丢弃的完整快照；同步约5Hz、模拟仍约10Hz，减少完整战役历史和重复JSON解析。状态效果查询缓存不改变战斗数值。
- 此特色服务器可配置 Node/V8 运行时执行原共享 TypeScript 内核，默认便携构建仍保留 Goja。Node进程故障不会悄悄切换到另一份模拟；确认停止的战局按服务器中断处理。

同一台1核服务器、同一份2943单位存档，30帧回放均值由561.4ms降至31.6ms，原始同步数据量下降约80%。这是服务端回放结果；实际客户端帧率在面板中独立测量。配置、验证与平台说明见 `docs/server-performance.md`。

# 0.3.7：按到站和新增兵力实时续派

- 玩家持续兵线脱离 6 游戏小时生产周期，在内核更新时调度到站和新出现的兵力；临时营地、教学楼等据点一致适用。
- 首次画线和自动续派统一遵守防守、守卫、待命的留守限制与派兵比例；姿态切换和总动员及时更新调度。
- 派兵额度与已处理驻军记录随存档保存，避免逐帧重算、刷新或读档反复抽走留守兵力；单兵到达累计小数额度，路径失败不消耗额度，公交乘员不拆组。
- 更新旧版“每6小时续派”的确认提示。每6小时仍用于宿舍生产等既有规则，不再限制玩家持续兵线的派兵时机。

服务器须重建共享内核；`kernel.playerDispatchVersion: 1` 标识实时派兵版本。见 `docs/realtime-dispatch.md`。

# 0.3.6：极速对局、战绩结算与校币商店

- 特色服务器新增极速玩家匹配与极速标准 AI：8 月 19 日 20:00 开战，固定 4×，不消耗倍速卡。常规与极速使用独立玩家队列；极速 AI 难度由服务端固定。
- 经验为击杀人数＋有效占点次数＋胜利 100；有实际击杀或占点才获得胜利加成。极速总经验乘 50% 向下取整。无战绩秒投降及无交战秒胜都不发经验。
- 每 5 点本场经验获得 1 枚本方校币，两校分别保存。商店以 100 校币购买 2× 卡、250 校币购买 4× 卡。购买有服务端定价、防重复扣费和保存失败回滚。
- 击杀和夺点由内核累计，夺回据点再次计数，原地持有不计数；投降、断线和自然胜负共用权威战绩结算，重复通知不重复发奖。入门倍速奖励只在升级跨越门槛时发放，不再每局补回用掉的卡。
- 固定特色对局的人类阵营席位，等待入场或断线不会改为 AI。初始事件和合法驻扎位置在首份快照前生成；客户端接收相同状态，初始驻军不再带着集合移动目标。
- 玩家营地兵线参加每 6 游戏小时的持续派兵；外校增援事件保留玩家兵线。新玩家请求全量快照不会吞掉其他玩家等待接收的增量更新。

需同时重新构建服务器共享内核和账号插件。具体规则和验证见 `docs/server-modes-economy.md`。

- 配套AI内核补充标准难度接敌兵力判断与可行营地绕行，原伤亡比失败场景已通过。需重新构建服务器，`/api/info` 中 `kernel.aiTacticsVersion` 应为1；详见 `docs/ai-camp-tactics.md`。

- 生涯改为点击顶部指挥官进入；主侧栏卡牌位置是外观收藏。生涯有左侧阵营切换、个人档案、等级奖励和六类勋章成就。

- 新等级奖励需显式领取，服务端校验账号、阵营经验、等级与领取记录，并持久化防重；旧经验、饰品、卡片与前6级解锁规则保留。
- 1v1 对局左右上角显示自己和对手的昵称、阵营、等级、图标与连接状态；AI 对手明确标注。全局聊天复用权威 WebSocket，仅展示全局频道，移除插件页的旧阵营聊天入口。
- 决策与研发按钮改为居中的完整 SVG；插件身份牌与聊天加入游戏的层叠上下文，完整的决策、研发、设置界面覆盖它们。
- 双人测试已验证消息双向收发、刷新重连与历史恢复；成长测试覆盖351级分页、350级饰品领取装备、重复领取、重启持久化和失败回滚。
- 与之配套的共享内核兵线修复需要重新构建原生服务器；插件本身不再自动产生调兵命令。见 `docs/order-lifecycle.md`。

## 0.3.3 历史说明

紧急修复：网页使用明确的玩家操作接口发送命令，不再扫描地图状态差异。插件拒绝旧版自动差异命令，防止覆盖调兵和总动员；确认逻辑使用完整权威状态缓存。前端收到状态时不再移动士兵、重算服务器寻路或保留旧姿态，位置平滑只改变显示对象。此版本需要同步部署的新版网页资源。

兼容原版服务器 v0.3.1；只需替换 `qingbei-account-hub`（Windows 加 `.exe`），无需替换服务器或逻辑内核。

- 对局使用插件自己的页面入口，自动使用账号昵称和已选阵营，不再显示原版二次选择页。
- 对局只能投降；未完成战斗会从个人主页自动返回，主页变更操作由插件 API 拒绝。
- 关窗/连接关闭后提供 60 秒返回期；使用 SSE 在线连接与心跳确认兜底识别突然断网。无关旧标签页的关闭不会使新连接掉线。
- 超时重连不能撤销已经成立的判负；双方同时离线则作废。服务器重启导致内核不存在的战局不计胜负和经验。
- 修复大批调兵分片被原版服务器内核忽略：插件先还原完整命令再交给原 WebSocket，保持命令序号、内容与服务器校验不变。
- 命令确认只依据服务器状态，不把本地动画或其他目标的移动当成成功。

更新前建议结束正在进行的战局。账号、密码摘要、经验和饰品保存在原数据文件中，不随插件替换而清空。会话目前保存在内存，重启后需要重新登录。
