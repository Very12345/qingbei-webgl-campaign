# v0.3.11：保持逻辑的开销优化

开发前存档：`codex/checkpoint-before-equivalent-cpu-6aecf81`。参考版本为已发布v0.3.10。没有调整模拟频率、AI周期、派兵间隔、寻路代价、战斗数值、奖励或房间上限。

## 改动

1. 增量同步直接比较单位与已有量化记录，仅为变化的单位分配新数组。保持22字段、舍入方式、空值、创建/删除顺序和消息触发条件。已有包中的数组不被复用修改。
2. 已完成决策列表逐项相同时复用效果，避免每个单位重复join生成字符串。列表变化仍进入原缓存键与原计算路径，同长度修改、稀疏数组和重新填入元素都能识别。
3. 只有派兵额度已结算至无可派额度时才缓存结果。下一帧逐项比较驻军身份、人数、可派状态、比例、留守数、目标及账本数据，任一输入变化就执行原算法。缓存内容为私有紧凑数组，不进入存档或网络。仍在每帧扫描驻军，新增/到站、失去单位、重新获得额度均及时处理。

## 性能测量

同一台1核服务器、Node v24.20.0，四个独立私有工作进程，360帧、100ms步长、4倍速、每两帧生成增量，使用既有2943单位存档副本。仅在线上无对局时以低优先级测量；交换新旧测量顺序后复测。

|顺序|旧CPU时间|新CPU时间|下降|旧批次P95|新批次P95|
|---|---:|---:|---:|---:|---:|
|新版先测|20316ms|19777ms|2.7%|142.7ms|144.7ms|
|旧版先测|21130ms|20012ms|5.3%|166.7ms|153.9ms|

收益比前一轮小，不能据此宣称大幅提高并发容量。该样本工作进程RSS没有下降，尾延迟存在波动。这里是内核及私有进程协议的离线测量，不包含真实玩家连接、Go宿主及TLS的完整负载。

便携Goja后端另做隔离比较：旧版约45.2–46.4ms/帧，新版约40.4–40.9ms/帧；每帧分配量约24.80MB降至18.65MB（分配总量，不是常驻内存）。`BenchmarkHostFrame`新增仅测试使用的`QINGBEI_PERF_REFERENCE_BUNDLE`参数，以相同推进与同步路径比较旧内核，区别于早期Goja全快照路径的历史基准。

原始数据在本地忽略目录`work/ui-review/v0311-*`与服务器私有目录`perf-v0311/`。缓存初版和并行测试时的试验结果不作为本表数据。
