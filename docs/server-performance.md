# v0.3.8 性能与同步诊断

开发前存档 `codex/checkpoint-before-server-performance-ed341ef`。变更同时涉及共享内核、Go宿主的网络传输和特色插件的调试界面，原游戏规则仍由同一份 TypeScript 代码执行。

## 已定位问题

1. WebSocket发送队列把较早的 `state_delta` 直接覆盖。增量包不是完整帧，慢连接会漏掉只发一次的兵线、新单位或删除更新。现在按实体ID合并未发送变更，保留必要的创建、删除及战役数据；快照有版本水位，读档/重置使用新代次。
2. 服务端每100ms调用 `step()`，生成、跨运行时导出、编码并解码一份完整地图，随后丢弃，再生成增量包。现在只推进，增量JSON直接传输。
3. 每次时间或随机种子变化都会重发完整战役历史。时间已有独立字段，现在仅有实际战役信息变更时携带完整战役数据。保存所需的派兵账本不进入显示用同步数据。
4. 状态效果对大量单位反复执行线性成员查询与相同倍率计算。缓存成员集合和稳定倍率，在成员数组替换、长度变化、效果属性变化及到期时失效；内核帧内添加效果仍及时失效。
5. 顶部通知停留“已发送”，与短暂的确认提示不一致。现在通过插件状态事件更新，区分发送、接收、处理和权威状态匹配。处理回执不等同于生效确认。

## 可选 Node 运行时

Goja 为便携构建的默认后端。特色服务器配置：

```text
QINGBEI_KERNEL_ENGINE=node
QINGBEI_NODE_PATH=/home/ubuntu/qingbei-plugin-server/runtime/node-v24.20.0-linux-x64/bin/node
```

Node后台进程通过私有标准输入/输出协议调用内嵌共享JS内核，不另写游戏规则，不开放额外网络监听端口。每个战局使用独立运行时；读档释放旧实例，战局退出关闭进程。请求有大小和超时限制。明确配置的Node缺失时启动报错，不在进行中的战局上静默切换后端。

生产用Node v24.20.0来自[官方发行目录](https://nodejs.org/dist/v24.20.0/)，安装前核对官方SHASUMS256。只放在此服务器的runtime目录，用systemd服务专用环境配置启用；不修改全局Node安装或PATH。回退可恢复旧程序及服务环境配置。

## 诊断口径

`GET /api/performance?room=...` 读取缓存的资源及循环统计，不获取完整游戏快照，也不等待JS模拟锁。Linux下读取真实CPU累计时间、RSS和整机内存；服务CPU/RSS合计包含Go宿主与注册的Node工作进程。100% CPU代表一个核心，不是整机百分比。其他平台不伪造缺失OS指标，仍提供Go堆、模拟耗时和网络信息。

插件左下角性能按钮展开后分别显示服务端和客户端指标。低FPS、服务器步进超预算、状态包延迟、正常等人暂停和内核错误有不同提示。诊断只能指出当前可观测瓶颈，不把网络与服务器不可达武断归因给某一方。复制数据不包含账号、密码、Cookie或会话令牌。

## 同机回放证据

使用线上最近存档的副本（2943单位、145据点、46条玩家兵线、19个状态效果），在原1核Xeon Gold 5117主机空闲时，以低优先级运行30帧基准。每帧推进100ms、4×；新版网络按约5Hz生成。

| 路径 | 均值耗时/帧 | 同步数据/模拟帧 |
|---|---:|---:|
| 已发布v0.3.7 Goja路径 | 561.4ms | 120314字节 |
| 优化后Goja路径 | 约250–300ms | 23446字节 |
| 优化后Node路径 | 31.6ms | 23446字节 |

Node结果含本机进程通信开销。整体服务端回放耗时下降约94%，同步字节量约80%。它不是客户端FPS保证，也不是四场同时满载的压测结论。Go分配量指标不包含Node堆，不能把它当成整个服务的内存占用。

原始存档与测量输出仅在忽略目录 `work/ui-review/` 和服务器私有 `perf-v038/` 中，不属于发布账号数据。`BenchmarkHostFrame` 可用 `QINGBEI_PERF_REPLAY` 指定副本；`QINGBEI_PERF_LEGACY_BUNDLE` 仅用于基准对比旧内核。

## 验证

- Go测试覆盖增量合并、创建/更新/删除、快照顺序、暂停恢复、代次隔离，以及诊断接口不被模拟锁阻塞。
- Node/Goja同种子回放的网络状态对比、实例隔离、释放与关闭测试。
- 插件测试覆盖接收/处理回执不提前确认、逻辑目标确认、旧回执不清除新命令、诊断分类。
- 浏览器实测性能面板、兵线绘制与确认；一条本地测试命令处理约28ms、状态确认约128ms，待确认项归零。
- 原有持续兵线、实时续派、特色模式、类型检查与构建继续作为回归门槛。
