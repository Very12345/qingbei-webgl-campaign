# AI 接敌与临时营地修复

标准难度清华对静止对手的旧结果为1634 / 1405，伤亡比约1.163，超过1.1。逐步记录阵亡位置后，其中1430名死于途中拦截点：AI按远处目标的守军计算派兵，却没有计入首先交战的强点。

## 策略变化

- 标准AI沿实际寻路结果检查首次接敌点，按该处守军和已投入部队估算所需兵力。兵力不足时换目标或等待增援。
- 标准和困难AI都可为被强点阻挡的生产目标规划临时营地。第一段须能抵达营地而不穿过敌方控制区；第二段必须绕开原强点，并评估仍可能遭遇的守军。不可通行、水体、建筑、与据点过近或过长的绕路会被排除。
- 同一支部队只承担绕行部署或普通进攻中的一项，避免同一轮重复分配。营地保留集结目标，收到部队后按指挥预算和营地派兵比例出击。
- 仅在找到可行的营地方案但资金不足时，为AI保留80资源。在制装备先完成已付款批次，再按预算决定是否续产；玩家生产不受此保留影响。
- 营地尚有在途部队或驻军时，不因普通进攻命令超时而丢失目标。同一目标不重复建设营地。
- 困难AI会用附近、足够且未承担防守任务的预备队攻击暴露的敌方营地。守军估算按实际12单位战斗范围，避免把已远离的部队仍计为驻军。
- 营地出兵同样受进攻批次与谨慎姿态约束；侦察队不会随着营地堆积兵力膨胀为大军。

上述规则不增加攻击、防御、资源或人口倍率，也没有按特定地图点、目标日期或测试种子设置特殊待遇。

## 验证结果

默认种子 `0x51a7c0de`，16倍速，沿用原有矩阵阈值：

| 场景 | 己方 / 对方阵亡 | 伤亡比 | 获胜游戏时 |
| --- | --- | --- | --- |
| 标准北大，对手静止 | 1085 / 1485 | 0.731 | 709.92小时 |
| 标准清华，对手静止 | 1076 / 1325 | 0.812 | 686.88小时 |

两侧都在9月12—19日窗口内获胜。9个AI场景的原有断言全部通过，并新增标准AI必须实际使用营地的断言。基准现在记录营地与其中的驻留、出发部队。修复了镜像对局过早结束时检查脚本取不到9月26日样本而崩溃的问题；这种情况仍判为失败，没有放宽阈值。

营地诊断记录中，两侧标准AI各建立3个营地。清华三个营地分别接纳并派出97、80、94个单位；北大两个营地分别接纳72、93个单位，并派出47、61个单位。另一个北大营地接纳76个单位，但在采样中没有记录到出发，不能把它算作完成了绕行攻击。

额外种子42：标准北大伤亡比0.857，标准清华0.885，也均在原定时间窗口内获胜。有限种子测试不能代表所有开局。困难AI对静止对手的提速偏好（不早于8月25日）仍不是现有矩阵断言，本次没有宣称已统一调妥该偏好。

## 复现与构建

```text
npm run test:ai-routes
npm run test:ai-camps
npm run verify:ai
npm run benchmark:ai -- thu-standard-idle 42
npm run build:kernel
```

`test:ai-camps` 覆盖两阵营、两难度的可行绕行、不可绕行时拒建、资源不足时预留、避免重复派兵、在途目标不失效、敌方营地突袭和部队抵达后继续出兵。

原生服务器须重新构建。运行实例的 `/api/info` 应返回 `kernel.aiTacticsVersion: 1`，并保留 `orderRulesVersion: 1` 与 `decisionCancellation: true`。本地测试配置和账号仍放在未跟踪的 `work/ui-review/`，不属于发布数据。
