# 特色服务器：极速、战绩与军需

本次开发前存档：`codex/checkpoint-before-server-blitz-a2ce57b`，基于线上 v0.3.5 的 `a2ce57b`。界面、匹配、经验、账号货币与购买入口位于 account-hub 插件；普通游戏没有新增这些模式或商店。原生宿主增加明确的人类席位和可选初始场景，玩法和战绩仍由共享 TypeScript 内核负责。

## 对局

常规玩家对战、人机训练保留；另有极速玩家、极速人机两种入口。极速从 2026-08-19 20:00（战役第 84 小时）开始，以 4 倍速运行，不消耗卡，不可叠加卡。极速 AI 固定标准难度，HTTP 请求中伪造困难也不会绕过；玩家对战的两种节奏使用独立匹配队列。

极速不把跳过的准备时间补算为生产、校历奖励或 AI 调兵。后续事件正常触发。原生服务器将 `serverOpening` 传入共享内核，在首份地图快照前完成初始事件和合法驻扎；驻军目的地等于驻扎位置。`humanTeams` 在创建时固定，所以空席、等待连接、掉线均不会让 AI 接管玩家军队。未指定该选项的普通开放服务器仍使用原有自动补位行为。

双方完成快照握手才开始推进；人类席位掉线时暂停，恢复后继续。服务端暂停状态使用明确的 `pausedForPlayers` 标记；客户端和插件显示等待提示，同时保留真正的断网/无状态报警。

## 经验与校币

`本场经验 = floor((己方击杀人数 + 己方占点次数 + 胜利加成) × 模式系数)`。

- 胜利加成 100，仅在本方有实际击杀或占点时发放；失败没有固定参与奖。
- 常规系数 1，极速系数 0.5。
- 每次实际夺取敌方据点加一次；夺回再次计算。持续持有不累加，临时营地摧毁和求真倒戈不算据点易主。
- 击杀按战斗中被消灭单位的人数统计，不能由网页请求提交数字。
- `本场校币 = floor(本场经验 / 5)`，存入所用学校的账号余额。战场的研究资源与账号校币分别保存。
- 2× 卡售价 100 校币，4× 卡售价 250 校币。两校余额独立，卡加入同一账号库存；默认旧账号不追补历史校币。

本版本按“新增账号长期阵营货币”的解释实现校币。账号此前只有经验、卡片、饰品，没有独立货币余额。

自然胜负从受信宿主 hook 获取战绩，投降和断线通过受保护的 `/api/internal/battles/{room}/stats` 查询。无法确认战绩时暂不结算，保留待结算结果并重试。发奖与完成标记同次持久化，写入失败恢复内存余额。商店按账号、购买编号保存回执，重试和重启不会重复扣币。入门卡按等级跨越发放，防止少量战绩重复补卡。

## 持续兵线

从己方据点拖到另一据点发出的是持续兵线。v0.3.7 起，新增与到站兵力按据点姿态、派兵比例实时调度，临时营地同样适用；v0.3.6 的自动续派曾挂在每 6 游戏小时生产周期上，现已纠正。框选士兵后下达的是那批士兵的单次命令。来源失守、目标摧毁、手动取消或重画仍会正常改变线路。详见 `realtime-dispatch.md`。

本次修复三种不同问题：玩家营地被周期派兵排除、外校增援事件调兵后误清除玩家原线、为新玩家生成全量快照时重置共用增量基线。最后一种会让已连接玩家漏掉状态更新，即使服务器保留了线路。

## 验证

`npm run test:server-modes` 覆盖首帧驻军位置、极速日期、跳过奖励、营地后续派兵、夺回计数、外校增援保留路线、第二名玩家入场不吞更新。Go 测试覆盖固定人类席位、真实内嵌内核、统计接口鉴权、极速强制标准、两种玩家队列隔离、零贡献结算、防重复发奖、商店并发重试和失败回滚。

本地浏览器验证了极速标准 AI 无难度/卡片选择、购买后北大校币 500→400 与 2× 卡 5→6、零战绩投降显示 0 EXP / 0 校币。真实双人 WebSocket 测试记录第 84 小时开局、4×、1025 名初始士兵静止、持续兵线跨至少 24 游戏小时（4 个派兵周期）保持、掉线人类席位不由 AI 接管；最后一轮还验证等人时不推进且拒绝提前操作，掉线后暂停。诊断文件位于忽略目录 `work/ui-review/`，不是发布账号数据。

TypeScript 检查、网页构建、Go 全量测试、11 项插件协议与对局 UI 测试、新场景回归、持续兵线回归均通过。9 场既有 AI 矩阵保持原伤亡比和日期门槛，结果 `ok: true`。最终本地预览端口为 17947，服务器及插件均为 v0.3.6。正式部署需同步更新网页、内核和插件，并检查 `kernel.serverScenariosVersion: 1`。

旧 `kernel-smoke` 中“必须存在 guard”断言在已发布 v0.3.5 和本次版本均失败，两者相同种子姿态与伤亡完全相同；受压清华选择 defend。该断言调整为接受 guard 或 defend，仍要求至少两种据点姿态。
