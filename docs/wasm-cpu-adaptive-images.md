# v0.3.10：CPU 开销、WASM 可行性与自适应图片

Git 存档：`codex/checkpoint-before-cpu-adaptive-images-f0b56c3`。本版没有启用 WASM，没有提高服务器房间上限，没有改动战斗数值或派兵周期。

## 已实施的优化

Node CPU 采样使用现有线上战局存档副本（2943 单位、145 据点）与同种子回放。寻路、移动、增量编码及派兵账本均占用 CPU；热点不仅是纯数值计算。

- A* 的八个邻接距离只计算一次，保留原有 Math.hypot 数值、顺序、坡度权重与堆排序逻辑。
- 起点和终点位于同格时直接生成单点路径，不再反复更新 LRU 或挤掉有用的长路线。
- 原生宿主经 JSON 传来的地图在创建内核时恢复为 Uint8Array / Float32Array / Int32Array。浏览器已有的类型数组直接复用，避免每房间长期保留普通数值数组。
- 图片预先生成并嵌入插件，请求时不做缩放或转码，避免增加服务器计算负担。

## 同机回放与并发边界

在原 1 核服务器、Node v24.20.0 上，只有服务器没有在线战局时以低优先级运行。工具使用生产 `node_runtime.cjs` 的私有标准输入输出协议，每个模拟房间独立 Node 进程，预热 12 帧、测量 120 帧；每帧模拟100ms/4倍速，每两帧生成增量。第二轮交换新旧实现的测量顺序。

|离线房间数|旧版CPU时间|新版CPU时间|旧版批次P95|新版批次P95|旧版/新版工作进程RSS|
|---|---:|---:|---:|---:|---:|
|1|1979ms|1929ms|42.4ms|41.6ms|130.0 / 123.2 MiB|
|2|4314ms|3835ms|109.3ms|86.8ms|261.2 / 251.4 MiB|
|4，第一轮|9694ms|8335ms|210.8ms|165.1ms|515.0 / 494.4 MiB|
|4，反向测量|11543ms|7567ms|252.4ms|152.7ms|517.3 / 480.1 MiB|

四房间两次测量的 CPU 时间分别下降约14%和34%，有明显宿主/运行时波动，不视为固定收益。最终战局状态校验相同；本地复测逐条增量流的SHA256也完全相同。该工具可在后续WASM原型中复用。

这不是在线满载并发承诺：CPU统计包含工作进程和测量父进程，但不包含真实Go宿主、玩家WebSocket/TLS和渲染。批次P95仍超过100ms，说明四个重载房间同时推进会出现尖峰。不能把平均CPU节省比例直接换算成房间数量。

## WASM 是否值得做

可以考虑。当前采用的Node运行时支持加载WASM；[Node官方说明](https://nodejs.org/learn/getting-started/nodejs-with-webassembly)介绍了模块实例化与线性内存接口。适合先评估完整的A*搜索：静态地图只传一次，缓存命中仍由JS处理，缓存未命中才批量调用WASM，返回路径索引。

不建议把每次距离计算单独跨JS/WASM边界，也不能把当前对象密集的TypeScript内核直接当成一个编译开关。[AssemblyScript](https://www.assemblyscript.org/)是面向WASM的TypeScript风格语言；本项目的状态对象、集合、随机数与序列化仍需要明确的内存布局和接口设计。

下一阶段的通过条件：同一份真实地图、同一批命令、同种子回放；路径、控制点接战、取消/续派、最终状态和增量流一致；保留float32成本与float64评分语义；统计包括地图准备、路径复制、跨边界调用、初始化和并发尾延迟的端到端收益。默认Goja承载层没有本项目的WASM接口，因此应先做Node可选搜索后端，再决定是否推广。当前实测尚不能保证WASM能再提升多少。

- 根据屏幕宽度、封顶DPR、网络类型、带宽/延迟提示和省流量偏好选图。慢网或省流量优先小图。
- [Network Information API 并非所有浏览器可用](https://developer.mozilla.org/en-US/docs/Web/API/NetworkInformation)。没有信息时先显示小图，只有真实下载的含延迟吞吐足够快，才在空闲时升级一次；缓存命中不能被误认为网络很快。
- 选图脚本内联在样式前，新页面不请求旧PNG。正文、按钮、文字布局不依赖图片加载完成。
- 带v1的资源路径使用一年immutable缓存、ETag与304；图片修改后必须换资源版本。旧PNG端点保留以兼容旧客户端。
- 生成器：`python scripts/build-hub-images.py`（Pillow支持WebP）；生成文件已经提交，发布时无需Python或在线图片服务。

验证覆盖省流量/慢网/未知网络、小屏幕、真实吞吐与缓存分支、资源白名单、HTTP304及页面不引用旧PNG。本地浏览器实际选择960/512中图并完成主页视觉和登录检查。
